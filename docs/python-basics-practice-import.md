## Правила оформления

- В учебных примерах кода списки создаются обычными циклами с `append()`. Списковые включения (list comprehension) не используются.

- Один выбранный файл Google Drive соответствует одному уроку. В разделе списков сохранены 17 уроков по 17 файлам; объединения по папкам нет.
- В условиях используется единое обращение на «ты». В задачах на функции используются короткие описания аргументов и результата, код вызова и отдельный вывод. В остальных задачах ввод описывается формулировками «вводится» и «вводятся». Действия, ограничения и особые случаи оформляются отдельными пунктами нумерованного списка; каждый пункт — отдельный абзац.
- Искусственные диапазоны чисел, максимальные длины строк и максимальное количество вводимых элементов убраны.
- Числа, определяющие смысл задачи, сохранены: количество вводимых значений, пороги сравнения, команды остановки, номер месяца и гарантии существования соседнего элемента.
- Приглашения к вводу и подписи результата из исходников входят в условия, открытые примеры, ожидаемый вывод всех тестов и эталоны. Повторные приглашения в циклах также проверяются.
- Условия полностью описывают порядок ввода, типы значений, необходимые гарантии и оформление ответа. Отдельных секций «Входные данные» и «Выходные данные» нет.
- Каждый «Пример работы» — штатный блок `console` с единым сеансом: приглашение программы, введённый пользователем ответ, следующие сообщения. Строки располагаются в порядке выполнения, включая повторные приглашения и ответы внутри циклов. Пользовательский ввод отмечен `❯` и цветом, сообщения программы — обычным текстом. Повторяющееся пояснение обозначений перед примерами не выводится.
- В примерах виден ввод пользователя, как при запуске в терминале. В ожидаемый ответ автоматической проверки этот ввод не добавляется.
- В уроках с теорией первый шаг — отдельное напоминание: цель, объяснение, пример на других данных с пошаговым разбором, частая ошибка и вопрос для самопроверки. Используются подзаголовки, таблицы и цветные блоки. Вся теория темы остаётся в одном шаге без задачи и тестов.

## Обновление существующего курса

Формат пакета 2 различает практические шаги (`kind: task`) и напоминания (`kind: theory`).
У напоминаний `task: null` и пустой список тестов. Старый формат 1 читается для проверки предыдущей версии.
Модели базы и формат блоков редактора не менялись.

Импорт по умолчанию проверяет пакет без подключения к базе. Запись выполняется только с `--apply`
и явно выбранной средой/URL. Новый курс создаётся черновиком. Статус публикации существующего курса сохраняется.
Совпадающий пакет даёт `unchanged`; несовпадающий курс отклоняется без перезаписи.

Для согласованного обновления передаётся `--update-from` с предыдущим пакетом. Перед записью весь текущий
курс должен совпасть с этой версией; чужая или более свежая ручная правка прерывает обновление.
Сопоставление идёт по исходным ключам документов и заданий, поэтому сохраняются ID разделов, уроков,
практических шагов, задач и тестов. Новые ID получают только теоретические шаги.

Обновление выполняется одной транзакцией с блокировкой курса. Состав практических задач и тестов
не меняется. Ошибка откатывает все изменения. Полные локальные дампы и предыдущие пакеты сохранены в `.codex/python-practice-before-revision/`
и `.codex/python-practice-before-console-examples/`; каталоги не отслеживаются Git.
