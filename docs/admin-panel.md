# Администрирование пользователей и отправок

## Подготовка

После обновления кода примените миграции в окружении приложения:

```bash
python -m alembic upgrade head
```

В Docker Compose миграции уже выполняются командой запуска приложения:

```bash
docker compose up -d --build app worker
```

Миграция `d95f3b8c421a` добавляет пользователям `blocked_at` и `block_reason`,
а отправкам — индексы для общей ленты и истории пользователя.
Существующие аккаунты остаются активными, решения и прогресс сохраняются.

## Страницы

- `/admin` — курсы, экспорт полной БД и навигация по административным разделам.
- `/admin/users` — поиск по имени, email и ID, фильтры по роли, блокировке
  и текущей записи на курс. Сортировка: сначала новые аккаунты.
- `/admin/users/{id}` — профиль, записи на курсы, прогресс, последние отправки,
  блокировка и разблокировка. История курса видна и после отписки.
- `/admin/submissions` — отправки с фильтрами по автору, курсу, задаче,
  результату и датам. Сортировка: сначала новые отправки; при совпадении
  времени — сначала больший ID.
- `/admin/submissions/{id}` — автор, задача, результат, код с подсветкой
  Python и сохранённая диагностика. Для незавершённой проверки есть обновление.

Фильтры и страница списка сохраняются в URL. Даты фильтров включают оба
выбранных дня и относятся к UTC; даты в таблицах отображаются в часовом
поясе браузера. Размер страницы — до 100 записей.

## Доступ и блокировка

`POST /api/admin/database/export` скачивает custom-архив PostgreSQL только для
активных администраторов. Восстановление выполняется на сервере скриптом
`scripts/restore-server.sh`. См. [инструкцию по резервным копиям](database-backups.md).

Данные выдаются через `/api/admin/*` только пользователям с ролью `admin`.
HTML-страницы содержат оболочку интерфейса без персональных данных;
права повторно проверяются сервером при каждом запросе данных и изменении.
Хеши паролей не входят в административные ответы.

`PATCH /api/admin/users/{id}/block` принимает `blocked` и `reason`.
При блокировке непустая причина обязательна, максимум 500 символов.
Операция сохраняет аккаунт и учебную историю. Уже выданные JWT перестают
давать доступ к защищённым маршрутам; новый вход также запрещается.
После разблокировки ранее выданный неистёкший JWT снова работает.
Уже поставленные в очередь решения продолжают проверяться.

Собственный аккаунт заблокировать нельзя. Изменения блокировок сериализуются
блокировками строк администраторов: администратор, которого уже заблокировали,
не сможет завершить одновременную блокировку другого администратора.
Это также сохраняет хотя бы одного действующего администратора.

## Значение показателей

- Решено задач: количество **уникальных задач** хотя бы с одной отправкой
  `ACCEPTED`. Повторные успешные отправки не увеличивают показатель.
- Пройдено шагов: записи в `StepProgress`. Этот показатель учитывает
  отметки о завершении и показывается отдельно от решённых задач.
- Учебная активность: последняя дата посещения курса, отправки решения
  или сохранённого завершения шага. Последний вход показывается отдельно.
- Локальные результаты сохраняются со слов браузера, как описано в
  `local-task-checking.md`. `ACCEPTED` не всегда означает серверную проверку.
