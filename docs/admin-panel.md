# Администрирование пользователей и отправок

## Подготовка

После обновления кода примените миграции в окружении приложения:

```bash
python -m alembic upgrade head
```

В Docker Compose миграции уже выполняются командой запуска приложения:

```bash
docker compose up -d --build app worker
```

Миграция `d95f3b8c421a` добавляет пользователям `blocked_at` и `block_reason`,
а отправкам — индексы для общей ленты и истории пользователя.
Существующие аккаунты остаются активными, решения и прогресс сохраняются.

Адреса статических ресурсов содержат общую версию содержимого, например
`/static/v-…/js/admin-bootstrap.js`. При обновлении JS или CSS меняется весь
префикс, поэтому относительные импорты загружаются из той же версии и не
смешиваются с файлами из старого браузерного кэша. Обычные `/static/...`
ссылки поддерживаются; ресурсы повторно проверяются сервером через
`Cache-Control: no-cache`, включая ответы `304`.

Если модуль панели не загрузился или проверка доступа не завершилась за
20 секунд, вместо бесконечной надписи «Проверка доступа» появляется
сообщение с кнопкой «Повторить загрузку». Техническая ошибка сохраняется
в консоли браузера для диагностики.

## Страницы

- `/admin` — курсы, экспорт полной БД и навигация по административным разделам.
- `/admin/users` — поиск по имени, email и ID, фильтры по роли, блокировке
  и текущей записи на курс. Сортировка: сначала новые аккаунты.
- `/admin/users/{id}` — профиль, записи на курсы, прогресс, последние отправки,
  блокировка, разблокировка и полное удаление пользователя. В разделе «Курсы
  и прогресс» можно выбрать курс для записи, отписать пользователя или записать
  снова. История курса видна и после отписки.
- `/admin/submissions` — отправки с фильтрами по автору, курсу, задаче,
  результату и датам. Сортировка: сначала новые отправки; при совпадении
  времени — сначала больший ID.
- `/admin/submissions/{id}` — автор, задача, результат, код с подсветкой
  Python и сохранённая диагностика. Для незавершённой проверки есть обновление.
- `/admin/notifications` — отправка уведомлений одному, нескольким выбранным
  или всем ученикам. Перед отправкой показывается количество получателей.

Фильтры и страница списка сохраняются в URL. Даты фильтров включают оба
выбранных дня и относятся к UTC; даты в таблицах отображаются в часовом
поясе браузера. Размер страницы — до 100 записей.

## Доступ и блокировка

`POST /api/admin/database/export` скачивает custom-архив PostgreSQL только для
активных администраторов. Восстановление выполняется на сервере скриптом
`scripts/restore-server.sh`. См. [инструкцию по резервным копиям](database-backups.md).

Данные выдаются через `/api/admin/*` только пользователям с ролью `admin`.
HTML-страницы содержат оболочку интерфейса без персональных данных;
права повторно проверяются сервером при каждом запросе данных и изменении.
Хеши паролей не входят в административные ответы.

`PATCH /api/admin/users/{id}/block` принимает `blocked` и `reason`.
При блокировке непустая причина обязательна, максимум 500 символов.
Операция сохраняет аккаунт и учебную историю. Уже выданные JWT перестают
давать доступ к защищённым маршрутам; новый вход также запрещается.
После разблокировки ранее выданный неистёкший JWT снова работает.
Уже поставленные в очередь решения продолжают проверяться.

Собственный аккаунт заблокировать нельзя. Изменения блокировок сериализуются
блокировками строк администраторов: администратор, которого уже заблокировали,
не сможет завершить одновременную блокировку другого администратора.
Это также сохраняет хотя бы одного действующего администратора.

## Удаление пользователя и запись на курсы

Кнопка «Удалить пользователя» в карточке открывает окно подтверждения.
Для удаления нужно ввести email удаляемого пользователя.
`DELETE /api/admin/users/{id}` полностью удаляет аккаунт, записи на курсы,
отправки решений, прогресс, учебную активность, токены сброса пароля и счётчики
AI-помощи. Удаление необратимо; старые JWT больше не дают доступ к аккаунту.
Email можно использовать для новой регистрации. Собственный аккаунт удалить
нельзя. Другого администратора можно удалить; проверка действующего
администратора и блокировки строк общие с операцией блокировки аккаунта.

`PUT /api/admin/users/{id}/courses/{course_id}` записывает пользователя на курс,
включая черновики. Ученик получит доступ к материалам после публикации курса.
`DELETE /api/admin/users/{id}/courses/{course_id}` отписывает пользователя.
Оба маршрута возвращают `204`; повторная запись или отписка не создаёт ошибку
и не дублирует запись. Отсутствующий пользователь или курс возвращает `404`.
Запись на курс не снимает блокировку аккаунта.

Отписка требует подтверждения в интерфейсе, убирает курс из кабинета ученика
и сохраняет решения и прогресс. После повторной записи обучение можно
продолжить. Изменения касаются только выбранного пользователя и курса.

## Уведомления и домашние задания

Миграция `b39d7e6a820e` добавляет таблицы `notifications` и `homework`.
В разделе «Уведомления» выберите получателей, заполните заголовок и текст,
нажмите «Проверить получателей», затем «Отправить уведомление».
Поиск работает по имени и email; выбранные ученики сохраняются при смене
поискового запроса. Режим «Все ученики» включает все аккаунты с ролью
`student`, в том числе заблокированные, и исключает администраторов.

В карточке ученика `/admin/users/{id}` раздел «Домашние задания» показывает
историю назначений. Кнопка «Удалить домашнее задание» после подтверждения
удаляет выбранное назначение и связанное уведомление этого ученика.
Кнопка «Назначить домашнее задание» открывает форму
с заголовком, необязательным комментарием, обязательной ссылкой и
необязательной датой сдачи. Разрешены внутренние пути, начинающиеся с `/`,
и полные адреса `http://` и `https://`; исполняемые схемы и сетевые пути
`//host` запрещены. Назначение и связанное уведомление сохраняются одной
транзакцией. Назначение не записывает ученика на курс: для закрытых материалов
по-прежнему требуется запись на соответствующий курс.

В шапке авторизованного пользователя колокольчик показывает число
непрочитанных уведомлений и последние десять записей. Остальные доступны
на странице «Все уведомления». Открытие меню ничего
не отмечает прочитанным. Нажатие на уведомление сохраняет время чтения;
кнопка «Открыть домашнее задание» отмечает его прочитанным и ведёт прямо по
заданной ссылке. Это работает и из раздела `/homework` («Мои домашние задания»).
В `/notifications` доступны история с пагинацией и кнопка «Прочитать все».
У каждого получателя свой статус. Чтение не означает выполнения задания.
Внутренние защищённые страницы сохраняют адрес в `next` и возвращают к нему
после входа. Внешние адреса в `next` не принимаются.

Личные API `/api/notifications` и `/api/homework` всегда ограничены текущим
пользователем; чужая запись при изменении статуса возвращает `404`.
Административные операции доступны только активным администраторам:

- `GET /api/admin/notification-recipients` — поиск и пагинация учеников.
- `POST /api/admin/notifications/preview` — подсчёт получателей.
- `POST /api/admin/notifications` — рассылка (`recipient_mode`: `all` или
  `selected`, `recipient_ids`, `title`, `text`).
- `GET/POST /api/admin/users/{id}/homework` — история и назначение ДЗ.
- `DELETE /api/admin/users/{id}/homework/{homework_id}` — удаление конкретного
  ДЗ и связанного уведомления только у указанного ученика.

ДЗ и уведомления ученика удаляются вместе с его аккаунтом. При удалении
администратора назначенные им ДЗ у учеников сохраняются. Автоматического
определения выполнения, напоминаний и внешних каналов доставки нет.

## Значение показателей

- Решено задач: количество **уникальных задач** хотя бы с одной отправкой
  `ACCEPTED`. Повторные успешные отправки не увеличивают показатель.
- Пройдено шагов: записи в `StepProgress`. Этот показатель учитывает
  отметки о завершении и показывается отдельно от решённых задач.
- Учебная активность: последняя дата посещения курса, отправки решения
  или сохранённого завершения шага. Последний вход показывается отдельно.
- Локальные результаты сохраняются со слов браузера, как описано в
  `local-task-checking.md`. `ACCEPTED` не всегда означает серверную проверку.
