# AI-подсказки

В `.env` задайте:

```dotenv
AI_MODEL_1=идентификатор-первой-модели
AI_MODEL_2=идентификатор-второй-модели
AI_MODEL_3=идентификатор-третьей-модели
AI_API_KEY=ключ-ProxyAPI
```

Идентификатор модели копируется из каталога ProxyAPI. Запросы идут с сервера на
`https://api.proxyapi.ru/v1/chat/completions` по [единому API ProxyAPI](https://proxyapi.ru/docs/unified-api).
Ключ в браузер не передаётся. Если переменные не заполнены, приложение продолжает
работать, а запрос подсказки сообщает, что сервис не настроен.
Номера могут идти с пропусками: список сортируется по номеру, пустые значения
и повторяющиеся модели пропускаются. Переменные окружения имеют приоритет над `.env`.
После изменения списка перезапустите приложение. Старый `AI_MODEL` поддерживается
как запасной вариант, только если нет ни одной заполненной `AI_MODEL_X`.

Перед запуском обновлённого приложения выполните `alembic upgrade head`.
Docker Compose выполняет миграции при старте приложения автоматически.
После изменения `.env` перезапустите приложение (для Compose: `docker compose up -d --build app worker`).

В админке откройте **Пользователи → карточка пользователя → AI-помощь** и включите
«Разрешить AI-подсказки для этого пользователя». По умолчанию доступ выключен у всех,
включая существующие аккаунты. Менять настройку может только администратор.

После включения появится форма настройки:

1. Задайте общее количество запросов в день (от 1 до 1000).
2. Добавьте нужные модели из списка `.env` и задайте каждой дневную квоту.
3. Нажмите «Сохранить настройки». Сумма квот моделей должна равняться общему лимиту.

Например, общий лимит 4: первой модели выделяется 1 запрос, второй — 2, третьей — 1.
Повторять модель в нескольких строках нельзя. Чтобы запретить модель, удалите её
из правил пользователя. Выключение AI-помощи сохраняет настройки и потраченные запросы.
Изменение лимитов также не сбрасывает уже использованные за день запросы.
Пока подсказка пользователя готовится, изменение его правил отклоняется: сохраните их после завершения запроса.

Для существующих пользователей сохраняется общий лимит 10. Пока отдельные правила
не сохранены, используется первая доступная модель с квотой, равной общему лимиту.

После неудачной локальной или серверной проверки ученик увидит кнопку «Подсказка».
Она доступна при неверном ответе, ошибке выполнения/компиляции, превышении времени
или памяти. Для ожидающих, принятых решений и сбоев самой проверки подсказка не предлагается.
AI получает сохранённый код отправки, текстовые материалы шага и ограниченную
диагностику. Скрытые тесты, эталонные решения и персональные данные не отправляются.
Модель получает инструкцию дать короткий совет на русском без готового решения.
Ответ выводится обычным текстом рядом с результатом проверки.
Перед запросом ученик выбирает разрешённую модель. В списке показан остаток
для каждой модели, отдельно отображается общий остаток. Если квота одной модели
исчерпана, можно использовать другую в пределах её квоты и общего лимита.

На странице самой отправки в админке отображается отметка «AI-подсказка:
Использована / Не использована». Если ученик получил подсказку для этой отправки,
ниже показывается её сохранённый текст и название использованной модели.
У старых подсказок модель может быть неизвестна. Ошибки сервиса отметку не устанавливают.

Учитываются **успешные подсказки за календарный день по Москве**, общий лимит
и квота выбранной модели проверяются сервером. Лимиты общие для всех задач,
обновление в 00:00 MSK. Подсказка сохраняется для конкретной отправки; повторное
открытие, в том числе с другой выбранной моделью, возвращает уже полученный ответ
без нового запроса и списания. Чтобы получить следующую подсказку, отправьте новое решение.
Счётчики хранятся в PostgreSQL и сохраняются после перезапуска. Учёт ведётся по
идентификатору модели, поэтому перестановка `AI_MODEL_X` не обнуляет её расход.
Если модель удалена из `.env`, её сохранённые квоты не расходуются, пока она недоступна.
При замене модели обновите правила соответствующих пользователей в админке.
Расход до добавления учёта по моделям сохраняется в общем дневном счётчике.

Одновременные генерации одного пользователя отклоняются с понятным сообщением.
Сохранение подсказки, общий расход и расход выбранной модели выполняются одной транзакцией. При таймауте,
отказе провайдера, некорректном ответе или отмене серверного запроса транзакция
откатывается. Запрос ограничен 45 секундами; автоматических повторов нет.
При сетевой ошибке браузера сервер мог успеть сохранить ответ: повторный запрос
вернёт сохранённую подсказку без повторного списания.

Сервис обрабатывает отдельно исчерпание дневного лимита (429), занятость (409),
таймаут (504), некорректный ответ (502) и недоступность/перегрузку провайдера (503).
Тело ошибок провайдера, ключ, код и условия задач в логи ошибок не записываются.
Код свыше 30 000 символов не отправляется модели.
