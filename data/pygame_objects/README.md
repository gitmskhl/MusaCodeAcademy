# Генерация множества объектов

Второй раздел курса «Разработка игр на Python. Основы» (`python-gamedev-basics`), после «Знакомство с Pygame». Установлен в текущую базу: курс 3, раздел 17, уроки 100–104, степы 563–584.

Пять уроков, 22 степа, девять самостоятельных заданий:

1. **Много объектов: списки и генерация** — параметры кружка, вложенные списки, `append`, общий цикл рисования, случайные значения и таймер. Задание: новый неподвижный кружок каждые две секунды.
2. **Потоки объектов: падение и удаление** — собственная скорость объекта и отбор видимых объектов. Задания: Minecraft-rain и кружки с разной скоростью падения.
3. **Генератор частиц: два направления** — единый формат для частиц сверху и слева. Задание: смешанный поток двух типов.
4. **Мышь создает объекты** — координаты клика, текущая позиция курсора, удержание кнопки и случайные скорости. Задания: точки по клику, поток вверх из курсора и Mouse balls.
5. **Редактор фигур** — сохраненные объекты, предпросмотр и выбранный тип. Задания: Simple editor и Simple Editor 2.

Материалы рассчитаны на локальный Pygame. Готовые решения самостоятельных заданий в степы не включены; автоматическая проверка stdout не создается. Используются штатные блоки text, code, callout и image. Подсказки стоят после демонстраций в конце заданий.

## Источники и адаптация

`sources.json` содержит тексты и ссылки всех девяти документов пользователя, `source-mapping.json` связывает каждый документ с соответствующим заданием. Часть кода исходников была изображениями и не вошла в текстовую выгрузку: учебные примеры написаны заново, исходные изображения не копируются. Ссылки на пять видеопримеров из документов сохранены.

Задания дополнены конкретными размерами окна, начальными состояниями, интервалами и проверяемыми правилами. Изменения относительно источников:

- Minecraft-rain: выбран интервал 10 кадров; для потока вверх — 3 кадра, для Mouse balls — один шарик за кадр удержания.
- Таймер использует `timer -= 1` и сброс после `timer == 0`, как в предыдущей практике курса. Времена приблизительны при 60 FPS; `get_ticks`, блокирующие ожидания и новые системы таймеров не вводятся.
- Скорости названы `vx`, `vy`, с пояснением названий `dx`, `dy` из исходников. Для Mouse balls сохранен отдельный формат списка из источника.
- Добавлены явные правила полного выхода объекта и безопасный отбор в новый список без удаления во время перебора.
- Для точек принимаются кнопки 1, 2, 3; колесико исключено. Для редакторов используется только левая кнопка.
- Предпросмотр редактора рисуется контуром, поставленные фигуры — закрашенными; выбранный тип не меняет уже поставленные фигуры.

Технические пояснения сверены с официальной документацией: [мышь](https://www.pygame.org/docs/ref/mouse.html), [события](https://www.pygame.org/docs/ref/event.html), [randint](https://docs.python.org/3/library/random.html#random.randint).

## Файлы и проверки

- `content.py` — учебный материал и пять полных программ; всего 14 блоков кода, остальные — подписанные фрагменты.
- `materials.md` — текст для чтения с локальными GIF; `section.json` — экспорт в формате платформы.
- `render.py` — служебные образцы девяти заданий и воспроизводимый рендер через Pygame 2.6.1 с SDL dummy. Решения не входят в экспорт ученика.
- `images/` — девять GIF с игровым полем 800 × 600 и поясняющей плашкой 80 пикселей. Курсор обозначен белым крестиком; плашка и крестик не являются требованиями задания. Каждые шесть кадров программы сохраняется кадр GIF на 100 мс. При повторе демонстрация начинается заново. Цвета квантуются общей палитрой GIF; файлы меньше 800 КБ.
- `verify.py` — исполнение учебных программ и образцов: интервалы таймеров, независимые координаты и цвета, движение без событий, клики с координатами события, удержание и отпускание, оба направления потока, сохранение типов фигур, удаление соседних невидимых объектов, граничное касание, закрытие через QUIT. Все 600 кадров GIF побайтово сверяются с повторным исполнением и тем же квантованием; проверяются длительности кадров. Это проверка с SDL dummy, без ручного ввода в системное окно.
- `browser.py` и `browser-verification.json` — проверка API всех 22 степов, пяти переходов на первые степы, девяти GIF (HTTP, MIME и SHA-256), страниц раздела и всех степов при ширине 1440 и 390 пикселей. Подтверждены навигация, блоки кода и отсутствие горизонтального переполнения страницы. Выбранные страницы и кадры просмотрены визуально.
- `images.json`, `import-result.json` — привязки текущей базы; для другой базы создаются заново.
- `before-import.json` — снимок прежнего раздела, пяти уроков и 51 степа. Сверка всех полей до и после импорта, затем независимое чтение подтвердили их сохранение. Повторный импорт завершился без дубликатов.

Из корня проекта, с Pygame, Pillow и зависимостями приложения:

```bash
.venv/bin/python -m data.pygame_objects.render
.venv/bin/python -m data.pygame_objects.verify
.venv/bin/python -m data.pygame_objects.build --check --export
```

## Установка

Для текущей базы повторная сверка:

```bash
docker compose exec -T app mkdir -p /app/data/pygame_objects
docker compose cp data/pygame_objects/. app:/app/data/pygame_objects/
docker compose exec -T app python -m data.pygame_objects.build --apply --export --course-id 3
```

Для другой базы с тем же курсом и пятью предыдущими уроками скопируй каталог без `images.json`, `import-result.json`, `browser-verification.json` и `before-import.json`, затем используй ID нужного курса. В контейнере нужен также существующий `data/pygame_intro/content.py` с функциями построения блоков. Pygame для самого импорта не требуется; GIF уже подготовлены.

```bash
python -m data.pygame_objects.build --apply --export --course-id <ID курса>
```

При работе в Docker скопируй `images.json`, `import-result.json` и `before-import.json` из контейнера обратно в исходный каталог и обнови локальный экспорт.

Импортер блокирует строку курса, проверяет slug и наличие пяти предыдущих уроков. Добавляет только второй раздел. Изображения загружаются штатным StorageService с проверкой SHA-256 и повторно используются по имени с хешем. Весь импорт выполняется одной транзакцией; при ошибке новые файлы удаляются. Существующий раздел при повторном запуске сверяется, а при посторонних отличиях импорт останавливается без перезаписи.

Для повторения браузерной проверки запусти отдельный Chrome с портом 9226 и временным профилем, затем `.venv/bin/python -m data.pygame_objects.browser`. Скрипт использует существующего администратора локальной базы только для чтения и не выводит токен. Скриншоты сохраняются в игнорируемом `.codex/`.
