# Первый урок разработки игр

В курс 3 «Разработка игр на Python. Основы» добавлен раздел 9 «Знакомство с Pygame», урок 50 «Первое окно и игровой цикл». В уроке 11 теоретических степов, включая самостоятельную практику и вопросы для самопроверки.

Материал следует последовательности «запусти → обрати внимание на результат → объясни причину → добавь код»: две строки создания окна, `while True` с `pass`, размеры и зависание окна, получение событий без `for`, перебор событий с временным выводом, закрытие по крестику, `pygame.init()`, фон и показ кадра, разбор всего цикла, практика и самопроверка. Итоговый код сохраняет `while True`, отдельную переменную `events` и `exit()` из авторского плана. Ошибки двоеточий в исходном наброске исправлены.

Примеры предназначены для локального Python с установленным Pygame. Блоки кода не запускаются браузерным исполнителем платформы; автоматических задач с проверкой стандартного вывода нет.

## Файлы

- `content.py` — исходный материал и полные примеры программ.
- `materials.md` — весь урок для чтения.
- `section.json` — раздел, урок и степы в формате платформы.
- `build.py` — проверка схем и синтаксиса, экспорт и транзакционная загрузка.
- `images/` — четыре настоящих снимка окон Pygame: 800×600, 1000×400, синий фон и результат практики.
- `capture.py` — повторное получение снимков только окон примеров в X11-сессии; требует Pygame и команду ImageMagick `import`. Пример запуска: `DISPLAY=:0 python -m data.pygame_intro.capture`.
- `illustrations.py` — добавление снимков через хранилище изображений приложения и привязка к степам 2, 3, 8, 10.
- `images.json` — ID файлов в текущей базе, пути загрузок и SHA-256 исходных снимков. Для другой базы привязки нужно создать заново.

## Проверка и загрузка

Из корня проекта:

```bash
.venv/bin/python -m data.pygame_intro.build --check --export
```

Для работающего Docker Compose:

```bash
docker compose exec -T app mkdir -p /app/data/pygame_intro
docker compose cp data/pygame_intro/content.py app:/app/data/pygame_intro/content.py
docker compose cp data/pygame_intro/build.py app:/app/data/pygame_intro/build.py
docker compose cp data/pygame_intro/illustrations.py app:/app/data/pygame_intro/illustrations.py
docker compose exec -T app python -m data.pygame_intro.build --apply --course-id 3
```

Импортер проверяет ID и slug курса, добавляет материал только в пустой курс. При повторном запуске сверяет существующие названия, описания, порядок и содержимое всех степов. При отличиях останавливается без перезаписи. Повторная загрузка выполнена: совпадение подтверждено.

Снимки уже добавлены в текущую базу. При переносе в новую базу сначала загрузи текст урока без `images.json`, затем скопируй каталог `images` в `/app/data/pygame_intro/images` и выполни `python -m data.pygame_intro.illustrations --apply --lesson-id <ID нового урока>` внутри контейнера. Полученный `images.json` скопируй обратно и обнови экспорт. При повторной загрузке в текущей базе используй актуальный `images.json` также внутри контейнера.

Добавление картинок сверяет исходный материал урока и не перезаписывает посторонние правки. Файлы регистрируются в таблице `files`, проходят обычную проверку изображений приложения и вставляются как штатные блоки `image` с подписями. Повторный запуск использует те же файлы. Снимки получены в настоящей графической сессии и просмотрены; рамки и кнопки окна могут выглядеть иначе у ученика. Статичный снимок зависания не добавлялся: он не показывает, отвечает ли окно.

В степе «Проверь, что ты понял» — 7 вопросов о поведении программы и отдельный подробный разбор каждого: подзаголовки, примеры кода и заметки с ключевыми мыслями. Вопросы идут перед ответами, чтобы ученик сначала попробовал объяснить происходящее самостоятельно.

Проверены схемы 11 степов и синтаксис 12 примеров: 7 полных программ и 5 поясняющих фрагментов в самопроверке. Все 7 полных программ также запущены с Pygame 2.6.1 в отдельном временном окружении с SDL dummy: первый пример завершается, промежуточные циклы продолжают работать, обработчики завершаются по отправленному событию QUIT. У итоговой программы проверены размер поверхности 800×600, черный фон и вызов обновления до завершения. Это проверка исполнения без графического интерфейса; визуальное поведение окна и системную отметку «Не отвечает» она не проверяет.

Технические объяснения сверены с официальной документацией: [события](https://www.pygame.org/docs/ref/event.html), [окно и обновление дисплея](https://www.pygame.org/docs/ref/display.html), [инициализация](https://www.pygame.org/docs/ref/pygame.html).
