# ООП для школьников

Два раздела курса «Разработка игр на Python. Основы» (`python-gamedev-basics`, ID 3), после генерации множества объектов:

1. **ООП: классы и игровые эффекты** — раздел 18, уроки 105–111. Класс и объект, `__init__`, `self`, методы, списки, волны, частицы, пушка, наследование и полиморфизм.
2. **ООП: столкновения и взаимодействие** — раздел 19, уроки 112–118. Хитбоксы, монетки, платформы, этапы игры, факелы, здоровье, ключ, сундук и кристалл.

Школьная редакция: **14 уроков, 63 шага, 28 блоков кода, 16 основных заданий с 16 встроенными GIF и 6 ссылками на видео**. Есть дополнительная мини-практика с треугольной частицей и предложение общего проекта.

Начало разбито на небольшие шаги: понятная аналогия с чертежом → первая точка с двумя числами → передача координат → отдельное объяснение `self` → метод движения → рисование → список точек. Примеры сопровождаются разбором строк, ожидаемым результатом и маленькими опытами. Остальные объяснения тоже переписаны простым языком. Термины вводятся после знакомого примера.

Графические задания выполняются локально с Pygame. Каждая GIF стоит прямо внутри задания под «Что должно получиться», перед условиями. Видео указаны там, где ссылка действительно есть в исходном документе. В GIF показан результат, полный код решений ученику не раскрывается.

## Источники

[sources.json](sources.json) содержит тексты и ссылки всех 16 документов [папки пользователя](https://drive.google.com/drive/folders/1nY7L7xSCuVrgmlsFm7MypXhnqZ9o4OqI). В `source-media.json` зафиксированы ссылки, найденные при чтении структуры документов: шесть видеопримеров, папки ресурсов и количество встроенных изображений. Временные URI встроенных изображений не сохраняются. `source-mapping.json` связывает каждый источник с заданием, GIF и видео, если оно есть.

Код написан заново: часть примеров в документах была изображениями. GIF созданы воспроизводимым исполнением собственных демонстраций на Pygame. Это примеры по условиям курса, а не записи исходных видео. Картинки игровых предметов доступны по ссылкам из заданий; начать можно с геометрических фигур.

Окно демонстраций — 800 × 600, сверху добавлена поясняющая плашка 80 пикселей. Указатель и плашка не входят в требования задания. Шесть кадров модели при 60 FPS соответствуют одному снимку GIF на 100 мс. Одинаковые кадры объединены с сохранением суммарной длительности. При повторе состояние сбрасывается. Размеры файлов — меньше 1 МБ каждый.

Параметры заданий уточнены: диапазоны скоростей/размеров, время жизни, числа частиц, один эффект при угловом ударе, одна цель взаимодействия на E, сброс неполной секунды яда, многоразовый ключ и согласованное состояние кристалла. Отскок от платформ — простая модель вертикального удара с квадратным хитбоксом; в задании дана расстановка без начального пересечения.

Технические источники: [классы Python](https://docs.python.org/3/tutorial/classes.html), [рисование Pygame](https://www.pygame.org/docs/ref/draw.html), [Surface](https://www.pygame.org/docs/ref/surface.html), [Rect](https://www.pygame.org/docs/ref/rect.html), [time](https://www.pygame.org/docs/ref/time.html), [font](https://www.pygame.org/docs/ref/font.html).

## Устройство и проверки

- `curriculum.json` — редактируемый источник школьных уроков; `content.py` добавляет изображения по манифесту. `examples.py` — программы, использованные в учебном тексте.
- `sections.json` — экспорт платформы; `materials.md` — версия для чтения с локальными ссылками на GIF.
- `render.py`, `images/`, `render-verification.json` — детерминированные демонстрации и состояния. Служебные классы демонстраций не входят в уроки.
- `verify.py`, `verification.json` — исполнение пяти полных консольных программ, одного продолжающего фрагмента и трех графических программ; проверки движений, прозрачности, стен, отскоков, факелов и таймера здоровья. Проверяются все 28 блоков кода и схема платформы.
- `verify_media.py`, `media-verification.json` — повторное исполнение всех 16 сцен и попиксельная сверка каждого временного снимка GIF с учетом объединенных кадров. Проверяются длительности и правила сцен: четыре стены, числа частиц, сбор монеток, пять платформ, отскок, три факела, выход из зоны яда и смерть, ключ/сундук, два переноса кристалла и неподвижность выложенного предмета.
- `browser.py`, `browser-verification.json` — API и браузер на ширине 1440 и 390 пикселей: все 63 шага, 14 переходов на начало урока, 16 загруженных GIF по MIME и SHA-256, встроенные изображения и ссылки на видео. Используется существующий администратор только для чтения; токен не выводится в отчеты. Скриншоты в игнорируемом `.codex/`.
- `images.json`, `import-result.json` — ID текущей базы.
- `revisions/` — первая редакция и снимок перед ее обновлением. Старые 59 шагов сохранили ID и привязку к урокам, добавлены только четыре новых вводных шага (644–647). Два предшествующих раздела, десять уроков и 73 шага не менялись.
- `rewrite.py` — однократное преобразование сохраненной первой редакции в школьную. Для обычных правок меняй `curriculum.json`; повторно запускать преобразование не нужно.

Проверки из корня проекта:

```bash
.venv/bin/python -m data.pygame_oop.verify
.venv/bin/python -m data.pygame_oop.verify_media
.venv/bin/python -m data.pygame_oop.build --check --export
```

При необходимости пересоздать GIF сначала запусти `.venv/bin/python -m data.pygame_oop.render`.

## Установка и обновление

```bash
docker compose exec -T app mkdir -p /app/data/pygame_oop
docker compose cp data/pygame_oop/. app:/app/data/pygame_oop/
docker compose exec -T app python -m data.pygame_oop.build --apply --export --course-id 3
```

Обычный импорт создает разделы или сверяет уже установленные без изменений. Чтобы заменить именно сохраненную первую редакцию школьной, используй `--apply --revise --export --course-id 3`. Этот режим сверяет текущее содержимое с первой или уже обновленной редакцией; при чужих отличиях останавливается без перезаписи. Обновление сохраняет существующие ID, поэтому ссылки на шаги и записи прогресса не удаляются.

Все записи и загрузки GIF выполняются одной транзакцией под блокировкой курса. Перед изменением сохраняется снимок, после commit данные читаются заново. При откате новые файлы удаляются. Повторный запуск проверен без дубликатов.

Для другой базы не переноси `images.json`, `import-result.json`, `before-import.json`, `browser-verification.json` и `revisions/before-school-update.json`: они относятся к текущей базе. Импорт ожидает тот же slug и два прежних раздела. После установки скопируй манифест и результат обратно из контейнера и обнови экспорт. Для импорта нужен существующий код приложения; Pygame требуется только для генерации/проверки демонстраций.

Для браузерной проверки запусти отдельный Chrome с временным профилем и портом CDP 9227, затем `.venv/bin/python -m data.pygame_oop.browser`.
