# Линейные алгоритмы

Раздел добавлен в конец курса «Основы Python. Практика.» (`python-basics-practice`, ID 4 в локальной PostgreSQL). Раздел 16, уроки 93–97, степы 530–554. Статус публикации сохранён. [Первый степ](http://localhost:8000/python-basics-practice/steps/530).

| Урок | Теория | Задачи |
| --- | ---: | ---: |
| Минимум и максимум | 1 | 4 |
| Суммы и счётчики | 1 | 4 |
| Среднее и отбор по условию | 1 | 4 |
| Поиск, соседи и серии | 1 | 4 |
| Два лучших результата | 1 | 4 |

Всего 25 степов: 5 теоретических и 20 практических. В теории 10 примеров Python с проверенным выводом, пошаговые объяснения, таблицы состояния, частые ошибки и вопросы для самопроверки. У каждой задачи два открытых примера; всего 129 тестов: 40 открытых и 89 скрытых.

## Стиль и источники

Перед подготовкой изучены пакет курса `data/course_imports/python_basics_practice/course.json`, правила из `docs/python-basics-practice-import.md` и текущие степы работающей базы. Сохранены обращение на «ты», нумерованные абзацы условий, цельный диалог в блоке `console`, цветовой маркер пользовательского ввода `❯`, отдельный первый степ с теорией и штатные блоки `code` для Python. Ввод, подписи результата, равенства, повторы и случаи без подходящих данных описаны явно. Искусственные верхние ограничения не вводятся. В примерах применяются обычные циклы и `append()`, без списковых включений.

Из двух приложенных PDF включены все шесть задач:

- `v1.0 (1).pdf`: минимум из пяти, заглавные буквы, сумма положительных.
- `v2.0 .pdf`: среднее положительных, самая длинная серия, второе по величине среди различных чисел.

Условия и сообщения из примеров сохранены; уточнены пустая последовательность, отсутствие подходящих чисел, регистр букв и различие между повтором результата и вторым различным значением. Приглашения вынесены на отдельные строки, чтобы сохранить принятый формат диалогов курса. Ввод количества, чисел и ожидаемые ответы исходных примеров сохранены.

Пометка PDF о необязательном дополнительном домашнем задании относится к исходному документу. Все шесть задач включены в обычные практические степы согласно запросу пользователя. `sources.json` сохраняет извлечённый текст и SHA-256 документов; `source-mapping.json` связывает каждую исходную задачу с уроком.

## Файлы и проверка

- `content.py` — авторская теория, условия, независимо рассчитанные проверочные ответы и эталоны.
- `build.py` — проверка материалов, экспорт и транзакционное добавление раздела.
- `materials.md` — полная читаемая версия с теорией и открытыми примерами, без решений задач.
- `section.json` — пакет раздела с тестами, без решений задач.
- `import-result.json` — ID созданных материалов, проверка повторного запуска и сохранности прежних строк БД.
- `browser-verification.json` — проверка отображения и выполнения всех тестов в браузерном Pyodide.

Из корня проекта:

```bash
.venv/bin/python -m data.linear_algorithms.build --check --export
.venv/bin/python -m pytest tests/cli/test_linear_algorithms.py -q
```

Для тестов нужна выделенная PostgreSQL с именем, заканчивающимся на `_test`, через `TEST_DATABASE_URL`, как и в остальных тестах проекта.

Импорт выполняется только с явным указанием БД и ID существующего курса:

```bash
.venv/bin/python -m data.linear_algorithms.build --apply --course-id 4 --database-url-env MCA_LINEAR_DATABASE_URL
```

В `MCA_LINEAR_DATABASE_URL` должен быть заранее установлен URL нужной базы. Без `--apply` подключение к базе не выполняется. Новые материалы добавляются одной транзакцией с блокировкой курса, после последнего существующего раздела. Повторный запуск требует полного совпадения материалов, задач и тестов; при отличиях запись отменяется. Решения из `content.py` в базу и материалы ученика не попадают.

Раздел — самостоятельное дополнение к исходному пакету импорта курса из Google Drive. Файлы и счётчики исходного пакета не изменены; для этого раздела используется собственный импортёр. Не следует перезаписывать дополненный курс старым полным пакетом из шести разделов.

Проверяющая система сравнивает вывод. Требование самостоятельно реализовать алгоритм циклом остаётся учебным: структура ученического кода и сложность автоматически не проверяются.
