# Раздел «Словари»

Дополнение к курсу «Python. Основы»: 7 уроков, 22 теоретических степа и 70 задач с постепенным ростом сложности. У каждого урока 10 задач: 3 базовые, 4 средней сложности, 3 повышенной. Теория предшествует практике.

| Урок | Содержание |
| --- | --- |
| Что такое словарь | Пары ключ — значение, словарь и список, чтение по ключу, `len`, ключ в переменной |
| Добавляем, изменяем и удаляем записи | `d[key] = value`, замена, изменение счетчика, `del`, порядок добавления |
| Проверяем наличие ключа | `in`, `not in`, безопасное чтение и удаление, подсчет слов и символов |
| Перебираем словарь обычным for | `for key in dictionary`, значение через `dictionary[key]`, накопление, фильтрация, поиск лучших |
| Разбираем систему учета оценок | Имя → одна оценка; команды записи, поиска, удаления, переименования, повышения и отчетов |
| Список оценок по имени ученика | Имя → список; `append`, два уровня обращения, пустой список, независимые списки, вложенные циклы |
| Разбираем расширенный электронный журнал | Регистрация, накопление оценок, показ, отмена последней оценки, удаление ученика, очистка и отчеты |

Весь перебор словарей выполняется обычным `for key in dictionary`, без `.items()`, `.values()` и `.keys()`. Также не требуются `.get()`, `.setdefault()`, `.update()`, `.pop()`, включения, словари внутри словарей или обработка исключений. Частотные словари строятся через проверку ключа и присваивание.

Стиль соответствует предшествующим материалам: обращение на «ты», короткие объяснения, знакомые бытовые примеры, точные приглашения и ожидаемый вывод. В теории есть 17 запускаемых примеров. Системы разбираются от модели данных и минимального рабочего кода до расширения командами. В задачах на каждую команду явно заданы порядок дополнительного ввода, ответы и поведение при ошибках.

## Формулировки и примеры

Все 70 условий переписаны. Каждое начинается с того, что делает пользователь
и какой результат должна получить программа. Исходные словари вынесены
в читаемые блоки кода. В задачах на перебор объяснён формат записи имён
с оценками и прямо указано, что готовый код уже собирает словарь.

В командных журналах отдельно описаны цель программы, начальные данные
и действие каждой команды. Уточнены повторная запись, отказ без потери данных,
разница между отсутствующим учеником и пустым списком оценок, перенос и копия.
Исключены автоматически составленные указания «получи строку name».

138 открытых примеров показаны как диалог: вопрос программы, ответ пользователя,
следующий вопрос или результат. Ввод отмечен `❯`; пустой ввод и одни пробелы
объясняются отдельно. В примерах перебора используются полные имена. Самые
длинные сценарии журналов заменены короткими примерами с одной понятной целью.
Новые примеры выполняются и сверяются с вручную заданными ожидаемыми ответами.

Сохранены все 210 тестов, заготовки, авторские решения, режимы проверки и порядок
задач. 22 теоретических степа остаются прежними.

## Проверка

Эталонные решения задач выполнены на 210 проверочных сценариях с вручную заданными ожидаемыми ответами, включая 138 открытых и 72 скрытых сценария. Для двух упражнений без ввода достаточно одного фиксированного ответа; у остальных не менее трех сценариев. Отдельно выполнены все 17 примеров теории. Проверена схема каждого степа и синтаксис заготовок. AST-проверка запрещает перечисленные выше методы и включения в авторском коде.

В проверках есть неизвестные ключи, повторная запись, повторное удаление, пустой словарь и список, одинаковые имена, регистр, повторы оценок, порядок ключей и независимость списков. Командные сценарии проверяют сохранение состояния между операциями и отсутствие изменений после отклоненных операций.

Автоматический проверяющий платформы сравнивает ввод-вывод, а не алгоритм ученика. Ограничения на приемы работы со словарем входят в условия и объяснения; статический анализ здесь проверяет авторские решения и примеры.

## Файлы и команды

- `content.py`: теория, условия, заготовки, авторские решения и проверочные ответы.
- `wording.py`: тексты условий, пояснения к исходным данным и описание команд.
- `examples.py`: короткие открытые примеры; используется запись диалогов из `data/reinforcement/examples.py`.
- `build.py`: проверка, экспорт и загрузка в базу.
- `materials.md`: весь материал для чтения, без скрытых тестов и эталонных решений задач.
- `section.json`: структура раздела со степами, задачами и открытыми/скрытыми тестами; без эталонных решений задач.

Из корня проекта:

```bash
.venv/bin/python -m data.dictionaries.build --check --export
```

Загрузка в работающий Docker Compose:

```bash
docker compose exec -T app mkdir -p /app/data/dictionaries
docker compose exec -T app mkdir -p /app/data/reinforcement
docker compose cp data/dictionaries/content.py app:/app/data/dictionaries/content.py
docker compose cp data/dictionaries/build.py app:/app/data/dictionaries/build.py
docker compose cp data/dictionaries/wording.py app:/app/data/dictionaries/wording.py
docker compose cp data/dictionaries/examples.py app:/app/data/dictionaries/examples.py
docker compose cp data/reinforcement/examples.py app:/app/data/reinforcement/examples.py
docker compose exec -T app python -m data.dictionaries.build --apply --course-id 1
```

Импортер добавляет раздел после последней существующей секции, не меняя прежние материалы и их порядок. Загрузка выполняется одной транзакцией с блокировкой курса. Повторный запуск сверяет все описания, порядок, степы, заготовки, лимиты и тесты; при полном совпадении ничего не меняет. При несовпадении существующих материалов отказывается от записи. Решения сохраняются только в исходном авторском файле и не попадают в БД или выдачу ученику.

Для обновления только условий и примеров существующего раздела предусмотрен
режим со снимком исходных степов:

```bash
docker compose exec -T app python -m data.dictionaries.build --apply --course-id 1 --wording-baseline /tmp/dictionaries-before.json
```

Снимок — JSON-массив объектов с `step_id` и `content`. Обновление разрешено,
только если текущий текст совпадает со снимком; заготовки, лимиты и все тесты
должны совпасть с исходниками. Теорию этим режимом менять нельзя. Любое
расхождение прерывает транзакцию. Прежние условия сохраняются в
`backups/dictionaries_wording`. Повторное применение совпадающей редакции
не меняет данные.
