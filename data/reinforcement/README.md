# Закрепление пройденного материала

Материалы добавлены в существующую секцию 7 курса «Python. Основы» (курс 1).
Созданы уроки 35–42: семь тематических уроков по 10 задач и итоговый урок с 15 смешанными задачами. Каждый степ содержит одну задачу. Всего 85 задач, 283 проверочных примера: 170 открытых и 113 скрытых.

## Как сформулированы задачи

Все 85 условий отредактированы после проверки задачи 202 «Номера шкафчиков».
Сначала объясняется, что вводит пользователь и что должна сделать программа.
Термины и ограничения следуют после смысла задачи. В задачах с несколькими
действиями приведён короткий пример с пояснением результата.

Вместо отдельных блоков «входные данные» и «вывод программы» показан цельный
диалог: сообщение программы, ответ пользователя, следующий шаг. Ввод отмечен
знаком `❯`. Диалоги записываются при выполнении авторского решения и проверяются
по ожидаемому выводу. Это сохраняет правильный порядок вопросов и ответов даже
в задачах с командами и несколькими вводами. Пустой ввод и ввод из одних пробелов
объясняются под соответствующим примером. В `materials.md` они дополнительно
обозначены словами, чтобы их можно было увидеть.

В примерах задачи про шкафчики показаны количества 3 и 5 с соответствующими
номерами. Нулевое количество объясняется отдельно в условии. Заготовки, решения,
все 283 проверочных сценария, ID и порядок степов сохранены.

## Как учтен стиль курса

Перед подготовкой изучены текстовые блоки, примеры кода, условия задач и заготовки существующих уроков 1–34 из работающей базы. Видеоуроки учитывались по сопровождающим материалам; расшифровки видео не использовались.

- Обращение к ученику на «ты», прямые инструкции «Напиши», «Выведи», «Введи», короткие объяснения без формального языка.
- Бытовые сюжеты: покупки, билеты, копилка, кошелек, очередь, погода и соревнования.
- Точный формат сообщений в терминале. Приглашения ко вводу включены в ожидаемый вывод, как в существующих задачах курса.
- От коротких упражнений к сочетанию нескольких приемов. Первые 3 задачи каждого тематического урока базовые, следующие 4 средней сложности, последние 3 повышенной. В смешанном уроке по 5 задач каждой сложности; темы чередуются.
- Краткое напоминание после условия в первом степе каждого урока. У каждой задачи есть два примера диалога, а у функций — заготовка с готовым вводом и вызовом.
- Используются уже встречавшиеся конструкции: переменные, `print`, `input`, `int`, арифметика, `if / else`, `and`, `for`, `range`, `while`, `break`, списки, индексы, срезы, `append`, `remove`, `in`, `len`, `split`, функции, параметры и `return`. Словари, множества, генераторы списков, исключения и классы не требуются.
- Условия явно задают обработку пустых данных, границ, равенства, регистра и повторов. В сложных задачах есть сохранение исходного списка и использование одной функции внутри другой.

Разделение прежней темы «Циклы» на два урока позволяет отдельно закрепить известное количество повторений и ввод до команды остановки. Первая тема объединяет `print`, переменные, `input` и `int`, чтобы не создавать десятки однотипных задач. Ввод и вычисления используются также в следующих уроках.

## Файлы

- `content.py` — авторские условия, заготовки, вручную рассчитанные ожидаемые ответы и эталонные решения для проверки.
- `wording.py` — тексты всех 85 условий в понятной форме.
- `examples.py` — запись и проверка последовательности вывода и ввода для примеров.
- `build.py` — проверка схемы степов, выполнение решений на всех тестах, экспорт, добавление в пустую секцию и защищённое обновление формулировок.
- `materials.md` — текстовая версия всех задач с примерами и заготовками, без решений.
- `section.json` — данные степов, задач и тестов для повторного импорта, без решений.

Проверка сравнивает вывод по тем же правилам, что `worker/checker.py`: нормализует окончания строк и удаляет пробельные символы по краям всего вывода. Предписания об алгоритме (например, использовать цикл или вызвать вспомогательную функцию) остаются учебными требованиями: действующая система проверяет вывод, а не структуру кода. Проверка записи диалога также обнаруживает недостающие и неиспользованные входные строки.

## Проверка и повторная загрузка

Из корня проекта, с установленными зависимостями приложения:

```bash
.venv/bin/python -m data.reinforcement.build --check
.venv/bin/python -m data.reinforcement.build --export
.venv/bin/python -m data.reinforcement.build --apply --course-id 1
```

Для текущего Docker Compose, где база доступна приложению по внутренней сети:

```bash
docker compose exec -T app mkdir -p /app/data/reinforcement
docker compose cp data/reinforcement/content.py app:/app/data/reinforcement/content.py
docker compose cp data/reinforcement/build.py app:/app/data/reinforcement/build.py
docker compose cp data/reinforcement/wording.py app:/app/data/reinforcement/wording.py
docker compose cp data/reinforcement/examples.py app:/app/data/reinforcement/examples.py
docker compose exec -T app python -m data.reinforcement.build --apply --course-id 1
```

Импортер требует явный ID курса и ровно одну существующую секцию с названием «Закрепление пройденного материала». Обычный повторный запуск заполненной секции требует полного совпадения описаний, порядка, степов, заготовок, лимитов и тестов; иначе операция прекращается. Данные добавляются одной транзакцией с блокировкой секции. Решения не записываются в базу и не передаются ученику.

Для обновления только условий и примеров есть отдельный режим:

```bash
docker compose exec -T app python -m data.reinforcement.build --apply --course-id 1 --wording-baseline /tmp/reinforcement-before.json
```

Перед таким запуском в указанный путь нужно передать снимок исходных степов —
JSON-массив объектов с `step_id` и `content`. Обновление разрешено, только если
текущий текст каждого изменяемого степа совпадает со снимком. Заготовки, лимиты,
тесты и структура курса сверяются с исходниками и не меняются. Любое расхождение
прерывает транзакцию. Прежние условия сохраняются в `backups/reinforcement_wording`.
Повторный запуск после успешного обновления не меняет данные.
